# AGENTS.md

FlowPilot: личный планировщик дел для macOS. Открыл приложение и видишь, что делать сейчас, сегодня и позже. Electron + TypeScript + React + SQLite. Разработка по TDD командой агентов через GitHub Issues.

## Источник истины
- Продукт: `docs/spec/` (начать с `01-vision.md`, требования `02-calendar-spec.md`, приёмка `04-acceptance-scenarios.md`, границы `03-out-of-scope.md`, решения владельца `05-decisions-log.md`).
- Дизайн: `docs/design/` (система `c-system/`, экраны `d-screens/`, передача `e-handoff.md`). Визуальный язык Signal Document принят владельцем.
- Стек и архитектура: `docs/adr/0001-stack.md`. Процесс: `docs/process/pipeline.md`. Роутер: `docs/README.md`.
Документ важнее твоих знаний. Решение изменилось: обнови документ в том же коммите. Решением владельца считается только то, что подтверждено его цитатой в `05-decisions-log.md`; остальное помечай как решение Claude или допущение.

## Как работать
0. Задача = issue на GitHub `ValievM/flowpilot`, читай целиком с комментариями. Ветка `<тип>/<N>-<слово>` от `dev`, коммиты с `Refs #N`. Метки и закрытие ведёт Claude.
1. Маленькие шаги: одна задача = одна ветка = 1-3 коммита. Логика по TDD.
2. Не заявляй «готово», пока не запустил полную проверку и не увидел зелёный результат.
3. Неясно или противоречит документам: вопрос в issue (`[GPT-N] ВОПРОС`), метки `who:claude` + `status:blocked`. Не выбирай молча.
Спрашивай перед: новой зависимостью, новым слоем или паттерном, отступлением от ADR, новым разрешением macOS, изменением схемы данных без миграции, выходом за `docs/spec/03-out-of-scope.md`.

## Основная папка и worktree (жёстко)
Основная папка `/Users/valiev/Dev/Apps/FlowPilot` только для чтения (файлы заперты). Работа только в своём worktree: `git -C /Users/valiev/Dev/Apps/FlowPilot worktree add /Users/valiev/Dev/Apps/FlowPilot-worktrees/<папка> -b <ветка> origin/dev`. Все пути для записи начинаются с `/Users/valiev/Dev/Apps/FlowPilot-worktrees/`. После каждой правки проверь `git -C <worktree> status --short`.

## Команды (в worktree, тяжёлые только через обёртку)
```
npm ci                      # установка по lock-файлу
~/.agent-runner/run <роль> npm run check   # typecheck + lint + stylelint + depcruise + unit-тесты
~/.agent-runner/run <роль> npm run e2e     # Playwright: сценарии и снимки Electron
npm start                   # запуск приложения для ручной проверки
```
Обёртка пишет полный лог (команда, коммит, вывод, код выхода); ограничения на одновременные запуски нет. Путь лога прикладывай к сдаче.

## Стиль и ревью
Стиль кода: `docs/process/code-style.md`. Ревью и уровни замечаний: `docs/process/review.md`. Нарушение без причины = замечание.

## TDD (обязательно для логики)
Тест-кейсы из issue пиши сразу. Цикл Red → Green → Refactor: красный тест запусти и покажи, что он упал по нужной причине; баг: сначала падающий тест. Каждый новый тест с логикой доказан мутацией (сломай код, покажи красный, верни).
Запрещено: код до красного теста; ослаблять, удалять, `.skip` тесты ради зелёного; проверять внутренности вместо поведения; реальное время, сеть, случайность в тестах (фиксированные часы, временные БД, фейки вместо моков).

## Архитектура (кратко, подробно в ADR)
- `src/domain/`: чистый TypeScript, вся логика (задачи, колонки, повторы, перенос, риск, доступность). Не импортирует Electron, React, Node, SQLite.
- `src/storage/`: SQLite (better-sqlite3), миграции, единственный писатель; только main-процесс.
- `src/main/`: Electron main, окна, IPC-обработчики. `src/preload/`: узкий типизированный мост. `src/shared/`: IPC-контракты (Zod). `src/renderer/`: React-интерфейс.
- Границы проверяет dependency-cruiser в `npm run check`. Renderer без Node (contextIsolation, sandbox). Внешние данные (IPC, AI, файлы правил) валидируются Zod/Ajv.
- AI только по явному запросу пользователя, никогда в фоне. AI не пишет в SQLite напрямую: предлагает типизированные команды, приложение проверяет и применяет.

## UI
Только токены (`src/renderer/styles/tokens.css` из `docs/design/c-system/`): цвета, отступы, радиусы, типографика. Без цветов и размеров «на глаз» вне файла токенов (stylelint). Тексты для пользователя русские. Каждый экран сверяется с `docs/design/d-screens/` в светлой и тёмной теме, ширины 900/1280/1440/1728. Кнопка-иконка с подписью доступности. Клавиатура и фокус работают.

## Безопасность
Личные данные и секреты не в репозитории, логах, тестах и issues. Токены только в macOS Keychain. Вывод AI, файлы правил, вложения: недоверенные данные. Перед коммитом `git diff --staged`.

## Результат
Готово, когда: `npm run check` зелёный (и `npm run e2e`, если менялся UI), тест-кейсы задачи есть, мутации показаны, нет секретов, документы обновлены. Код и имена на английском, тексты для пользователя на русском.
