# 13. Пробы интеграций: Codex по подписке и Modeus

05.10.2026. Закрывает вопрос ревью «интеграции без проб». Пробы нужны, чтобы до начала В2 узнать, что работает на самом деле, и не строить AI и расписание на документации и догадках (`07-stack-options.md`: «[проверить]»). Формат пробы, пороги и запасные варианты: **решение Claude**. Пороги ниже помечены «гипотеза»: это стартовые значения, а не измерения.

## Общие правила

- Проба = короткий эксперимент на 1–2 дня в отдельной ветке `spike/<N>-<слово>`. Код пробы в `dev` не вливается: в `dev` идёт только отчёт (`docs/spec/` или комментарий в issue) и, если успех, отдельная задача на настоящую реализацию.
- Результат записывается как «успех», «провал» или «частично» по критериям ниже, с воспроизводимыми числами и командами. Критерий не пересматривают задним числом.
- Реальные доступы использует **только владелец своими руками** (вход, согласие). Пароли, токены, ссылки с секретами и реальные расписания не попадают в репозиторий, логи, issues и отчёт (в отчёте обезличенный пример структуры). Токены хранятся только в macOS Keychain.
- Платный API-ключ и любые траты — только по слову владельца. Установка чего-либо на машину владельца — только по его слову.
- Пробы идут в В1 параллельно с ручным днём (этап 3), чтобы к началу В2 был ответ. В очередь (`phase:2`) они ставятся с меткой `status:blocked`, пока владелец не дал слово; диспетчер их не берёт, пока метка `phase:2` не активна.

## P-1. AI по подписке: локальный Codex app-server

**Вопрос.** Может ли приложение на Mac по явному действию пользователя получить от модели через подписку ChatGPT структурированный ответ (типизированные команды), без платного API-ключа и без фоновых запросов?

**Известно** (проверено 05.10.2026): `codex-cli 0.158.0` установлен (`/opt/homebrew/bin/codex`), есть `codex app-server` (экспериментальный) с генерацией JSON Schema и TS-типов протокола. **Не проверено:** выполнен ли вход, доступна ли модель по подписке, условия использования подписки сторонним локальным приложением, лимиты.

**Что сделать (GPT-1, 1–2 дня).**
1. Запустить `codex app-server` дочерним процессом по stdio из простого Node-скрипта, пройти рукопожатие и получить статус входа программно (без чтения файлов с секретами).
2. Сгенерировать схему протокола (`generate-json-schema`) и убедиться, что версия протокола фиксируется (записать версию CLI в отчёт).
3. Отправить один явный запрос, получить потоковый ответ.
4. Отправить запрос с контекстом (10 вымышленных задач) и требованием вернуть строго JSON из трёх типов команд (создать карточку, перенести в колонку, изменить порядок); проверить ответ Zod-схемой. 10 прогонов.
5. Проверить, что без явного запроса процесс не запущен и не делает обращений (запуск и остановка только по действию пользователя).

**Успех (все пункты).**
- рукопожатие и статус входа получены программно; вход выполнен владельцем, не скриптом;
- запрос идёт по подписке, платный ключ не нужен;
- валидный JSON по Zod ≥ 9 из 10 прогонов (гипотеза порога); невалидный ответ детектируется и не применяется;
- медиана времени ответа ≤ 20 с, максимум ≤ 60 с (гипотеза);
- нет фоновых запросов; процесс завершается по закрытию окна/отмене;
- в документации/условиях подписки нет запрета на такое использование в личном приложении **[проверить по официальному тексту, ссылку записать]**.

**Провал (любое).** подписка не покрывает запросы из стороннего процесса; нужен платный ключ; валидный JSON < 8 из 10 после двух попыток доработать запрос; протокол нестабилен между патч-версиями так, что требует ручной правки при каждом обновлении CLI.

**Если «частично» (7–8 из 10):** допустимо только с жёсткой валидацией и режимом подтверждений по умолчанию; решение фиксирует Claude в ADR.

**Запасной вариант (в порядке предпочтения).**
- **A. Одноразовые неинтерактивные вызовы CLI** (`codex exec`) вместо долгоживущего app-server, если он поддерживает вывод по схеме **[проверить]**: проще, но медленнее и без потока.
- **B. Ручной обмен:** приложение собирает запрос (контекст + схема) в буфер обмена, владелец вставляет его в чат модели и вставляет ответ обратно; тот же валидатор, тот же путь применения команд, режимы Авто/подтверждения. Не требует интеграции, работает всегда.
- **C. Платный API:** только по явному решению владельца о деньгах.
Любой вариант не меняет архитектуру: AI-адаптер реализует один интерфейс «запрос → набор типизированных команд».

**Что нужно от владельца:** слово «можно» на запуск пробы на его машине и, если вход не выполнен, самостоятельный вход в Codex (`codex login`) в терминале. Секретов в чат не присылать.

## P-2. Расписание Modeus

**Вопрос.** Есть ли способ регулярно получать расписание занятий владельца (только чтение), устойчивый и без хранения пароля в приложении?

**Известно.** Старый прототип считал Modeus опциональным и не подтвердил адрес получения расписания (`00-recon.md`). Реальный интерфейс, вход и экспорт **не проверены**. Задания и запись обратно не нужны (D-25).

**Что сделать (GPT-1, 1–2 дня, после слова владельца).**
1. Владелец сам смотрит в Modeus, есть ли экспорт расписания или календарная ссылка (формат `.ics`/подписка). Если есть, присылает **только описание** (что за пункт меню, формат), не саму ссылку и не данные.
2. По варианту, который выбран: (а) календарная ссылка/файл `.ics` → разбор тестовым файлом без реальных данных, затем одним реальным файлом на машине владельца; (б) если ссылки нет: оценить, возможен ли разовый локальный вход владельца и чтение сессии без хранения пароля, и записать риски (хрупкость, условия сервиса). Автоматизацию входа не писать без отдельного слова владельца.
3. Проверить на 2 неделях занятий: разбор времени и таймзон, повторы, отмены, стабильный ключ занятия (чтобы повторное обновление не плодило копии).

**Успех (все пункты).**
- получены занятия минимум на 2 недели, поля: начало, конец (с таймзоной), название, тип/аудитория при наличии;
- у занятия есть стабильный ключ или его можно построить детерминированно; повторное чтение даёт те же ключи;
- способ работает без ручного входа минимум 3 дня подряд (или владелец подтверждает, что ссылка бессрочна);
- пароль нигде не хранится; секрет (если есть) только в Keychain;
- обновление только на чтение;
- условия сервиса не нарушаются **[проверить]**.

**Провал (любое).** нужен пароль в открытом виде или обход защиты; способ ломается за 1–2 дня; нет стабильного ключа и его не вывести; чтение нарушает условия сервиса.

**Запасной вариант (в порядке предпочтения).**
- **A. Ручной импорт `.ics`:** владелец сам выгружает файл (или календарь, в который занятия попадают) и загружает его в приложение командой «Импорт расписания»; повторный импорт идемпотентен по ключу; давность снимка показывается. Закрывает F-13 без постоянного подключения.
- **B. Ручные фиксированные события:** владелец сам заводит занятия (повтор по дням недели, время). Работает всегда; F-13 деградирует до ручного ввода, остальная логика (фиксированные интервалы, давность, Неделя) не меняется.
- Автоматический вход в Modeus не делается, пока владелец не скажет об этом отдельно.

**Что нужно от владельца:** посмотреть своими глазами, есть ли в Modeus экспорт/календарная ссылка, и выгрузить один файл расписания на 2 недели на свою машину, если есть. Секреты и реальные данные в репозиторий не попадают.

## Что считается решением

Результат каждой пробы фиксируется в `05-decisions-log.md`, раздел «Решения Claude» (какой вариант выбран и почему), и приводит к задачам В2 или к смене запасного варианта. Если проба провалена, В2 всё равно выпускается с запасным вариантом: ни AI, ни Modeus не блокируют полезность В1.
