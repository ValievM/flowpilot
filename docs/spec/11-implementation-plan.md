Обновлено 05.10.2026 (задача #1). Стек принят: `../adr/0001-stack.md` (решение Claude, основа `07-stack-options.md`). Состав выпусков: `02-calendar-spec.md`, раздел «Выпуски» (решение Claude). Это порядок работ, не оценка календарных сроков.

## Метки и выпуски

Метка `phase:N` в GitHub Issues = **выпуск**, не номер этапа:

| Метка     | Что                                                        | Этапы ниже                |
| --------- | ---------------------------------------------------------- | ------------------------- |
| `phase:1` | В1 «Ручной день»                                           | 1, 2, 3 и ворота В1       |
| `phase:2` | В2 «Помощник и расписание»                                 | 4, 5, 6, 7, пробы P-1/P-2 |
| `phase:3` | P1 после В2 (Неделя; меню-бар только по решению владельца) | —                         |

Диспетчер берёт задачи только активных меток (`.prompts/dispatcher.md`). `phase:2` включается, когда закрыты ворота В1 и есть результаты проб.

## Выпуск 1 «Ручной день» (`phase:1`)

Цель: открыл приложение и видишь, что делать сейчас, сегодня, позже, без AI, сети и сторонних входов. Требования: F-01–F-06, F-14, F-15 (`02-calendar-spec.md`).

1. **Каркас и сохранность.** Каркас проекта и проверки (#2). Typed domain (#3), SQLite с единственным писателем и миграциями, транзакции, проверка версии, история и отмена, вложения (файловое хранилище), экспорт и проверяемое восстановление, IPC-мост. Gate: сохранение, перезапуск и конфликт версии проходят руками и тестом; повреждённый импорт не заменяет данные.
2. **Ручной день.** Сегодня/Сейчас/Все задачи (фильтры включая «Позже»), доска и свои колонки, карточка/подзадачи/комментарии/вложения, быстрый ввод. Токены дизайна с первого дня. Gate: AC-01–AC-04, AC-13 (части В1); дела полезны без AI.
3. **Повторы и риск.** Экземпляры и пропуски, перенос незавершённого, оценка остатка в рабочих днях и риск срока по модели v1, настройка рабочих дней. Gate: AC-05, AC-09 (таблица чисел); не теряются пропуски, нет фиктивного точного прогноза.
   **Ворота В1: приёмка выпуска 1** (подмножество этапа 7, только то, что есть в В1): обе темы, ширины 900/1280/1440/1728, клавиатура и фокус, VoiceOver на ключевых экранах, файлы, чистая установка (`npm run make`, darwin arm64), сверка с `docs/design/d-screens/`. Gate: все части «В1» из таблицы в `04-acceptance-scenarios.md`, e2e зелёный, ручная приёмка владельцем. Владелец принимает В1 руками; без его слова `main` не обновляется.

Параллельно с этапом 3: пробы P-1 и P-2 (`13-integration-probes.md`), чтобы к старту В2 были ответы.

## Выпуск 2 «Помощник и расписание» (`phase:2`)

Требования: F-07–F-13 (`02-calendar-spec.md`). Порядок: правила → AI → Modeus → полная приёмка.

4. **Правила.** JSON Schema, проверка ссылок/конфликтов, импорт/экспорт, предыдущая активная версия, привязки, линтер. Gate: AC-08 и сценарии `10-rules-format.md`. Может идти до результатов проб.
5. **AI-адаптер** (после P-1; вариант по результату пробы: app-server, одноразовый CLI или ручной обмен). Контекст, чат, создание, перестройка, Auto/подтверждения, устаревшие предложения, учёт риска. Gate: AC-02 (чат), AC-06, AC-07, AC-12 (AI-часть); ни одного скрытого фонового запроса.
6. **Modeus** (после P-2; вариант по результату: подключение, импорт `.ics` или ручные события). Снимки, давность, ошибки; полоса расписания на «Сегодня», системные напоминания (F-12). Gate: AC-10, AC-11; сбой не обнуляет занятость. Доступ владелец предоставляет сам при реальном подключении.
7. **Полная Mac-приёмка В2:** весь набор AC, `../design/e-handoff.md`, упаковка и ресурсы.

## После В2 (`phase:3`)

P1-01 «Неделя» (приёмка AC-P1-01). Меню-бар, глобальные горячие клавиши, vibrancy — только после отдельного решения владельца.

## Правила параллельной работы

Параллельно допустимо после стабилизации контрактов и с явным владением файлами: `src/domain`, `src/storage`, `src/main` и IPC-контракты (`src/shared`) — GPT-1; `src/renderer` — GPT-2; инфраструктура, e2e, CI, документы — GPT-3 (`../process/pipeline.md`). Контракты IPC и доменные типы меняет только их владелец через issue. Задача, зависящая от открытой, ставится с `status:blocked` и строкой `Зависит от: #N`.
