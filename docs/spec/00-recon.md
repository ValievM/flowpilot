## Главные противоречия

1. **Состав MVP:** drag-and-drop и preview diff стоят в экране MVP (§16.2), но FR-CAL-011 и FR-PLAN-011 — P1/V1. Три пресета алгоритма обещаны в §11.5 для MVP, а §23.2 относит их к V1. Добавление почты/Modeus (§3.4.1) не отражено в итоговом списке MVP (§23.1).
2. **Подтверждение изменений:** T14 обещает сначала AI-черновик, затем подтверждение. `UI/App.svelte:493` сначала вызывает применяющий `replan`, затем получает рекомендацию. Это разные пользовательские сценарии.
3. **Почта «только чтение»:** §3.4.1 и T13 запрещают изменения писем; открытие письма вызывает `MarkRead`, а сервис обращается к серверу для изменения отметки прочтения (`UI/App.svelte:132`, `S/mail.go:163`).
4. **Распределение времени:** §11.4 требует сортировку по срочности и сложности размещения, код сортирует сначала по приоритету (`D/planning/planning.go:436`). Буфер в FR-PREF-003 считается от доступного времени, в коде — от дневного лимита (`:276`).
5. **Защита ближайшего времени:** §11.2 допускает изменение freeze window только при риске дедлайна, §11.5 — при любом нарушении обязательного ограничения. Не определено поведение при новой встрече без угрозы дедлайну.
6. **Полномочия AI:** §10.5/15.3 требуют подтверждаемых предложений; `AGENT_TASKS.md` §8.2 описывает MCP с прямыми изменениями после общего переключателя. Это документальное противоречие; MCP-адаптер здесь не проверялся.
