# 03. Что не входит в первый выпуск

04.10.2026. Рабочая граница выпуска. Пункты с прямыми ответами владельца опираются на журнал; остальные обозначены как предложения аналитика и ещё не являются согласованным объёмом.

## На основании ответов владельца

| Не делаем сейчас | Почему / основание |
|---|---|
| Телефон, веб-клиент и синхронизацию между устройствами | Сначала Mac, телефон отложен: D-24. Веб-клиент отдельно не запрошен. Будущая синхронизация остаётся направлением, а не текущей работой. |
| Специальные импортёры учебных заданий под дисциплину/семестр | D-25: задания передаются через чат, AI создаёт карточки. Расписание поступает из Modeus. |
| Почтовую интеграцию, Apple/Google Calendar и прочие внешние коннекторы | Первым выбран Modeus, остальные позже: D-23. Это не отказ от будущих интеграций. |
| Фоновую переприоритизацию через AI при каждом изменении | D-17: перестройка только кнопкой или сообщением. Начало дня само по себе не вызывает модель. Это не запрещает обычное обновление данных интеграции без AI. |
| Обязательную точную оценку всех задач, бюджет часов и диалог перед началом дня | Владелец отменил бюджетный сценарий: хочет видеть дела и начать. Приблизительная оценка для раннего риска срока остаётся в продукте по последнему уточнению. |
| Самостоятельные карточки подзадач с собственными датами | D-22: отмечаемые пункты внутри родительской карточки. |
| Обязательные многоэтапные процессы для каждой задачи | D-09/D-19: простые состояния и подробная карточка. Свои колонки разрешены, но не навязывают процесс. |

## Предлагаем отложить

| Не включать без отдельного решения | Обоснование аналитика |
|---|---|
| Команды, роли сотрудников, спринты, сложные зависимости и отчётность проектов | Владелец описывает личное ведение дня. «Как в компании» относится к содержанию карточки, не доказывает потребность во всём наборе Jira. |
| Генерацию учебных отчётов и ГОСТ-документов | Есть в старом проекте, но не входит в подтверждённые новые сценарии. |
| Таймер, аналитику продуктивности, серии достижений и недельные квоты привычек | Пока не нужны для описанных сценариев. Простые повторяемые дела остаются в первой версии. |
| Изменение записей в Modeus | D-25: нужен импорт расписания; обратная запись не запрошена и технически не проверена. |
| Произвольный исполняемый код в документах правил | Задача документа — описывать важность и ограничения. Пользовательские формулы/скрипты не запрошены. |
| Перенос всей существующей реализации без проверки полезности | Старое ТЗ и выбранные ранее технологии не являются обязательными. Список переноса/переписывания появится после согласования продукта и сравнения стека. |

## Граница обещаний

Отдельная беседа о том, увеличивать ли бюджет времени, исключена из обязательного сценария. Владелец сам решает, открывать ли чат; запрос «что делать сейчас?» поддерживается.

AI не обещает точную вместимость дня при неизвестной длительности задач. Линтер проверяет формальную структуру и распознаваемые конфликты, а не гарантирует правильное понимание любого свободного текста. Возможность импортировать конкретные данные Modeus требует проверки; обходные пути с реальными аккаунтами в рамках подготовки спецификации не запускаются.

Будущая поддержка телефона учитывается как критерий сравнения стека и переносимости данных. Это не означает разработку облачного сервера, синхронизации или мобильного клиента в первом выпуске.

Эти границы используются при реализации; дополнительные исследовательские макеты не повышают автоматически функции до P0.
