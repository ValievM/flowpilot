# 07. Сравнение стеков и рекомендация

04.10.2026. Основа — итоговая модель задач и принятый визуальный язык. Владелец попросил «подготовь итоговый пакет с результатом в ходе двух промптов», затем «доделывай». Это основание завершить техническую рекомендацию, **не цитата о выборе конкретного стека**. Ни один вариант в этой задаче не собирался; оценки скорости и поддержки — инженерное суждение, не бенчмарк.

## Сравнение

Табличные оценки — вывод из требований проекта, не утверждения этих источников.

## Рекомендация: Electron + TypeScript + React

Причина: для этой версии важнее быстро и точно реализовать уже выбранный интерфейс, проверяемую модель задач, чат и локальную интеграцию; всё прикладное поведение получает один язык и короткий цикл проверки. SwiftUI предпочтительнее, если после рабочего прототипа окажется критична полностью нативная поверхность или скоро начнётся iPhone-клиент. Tauri — разумная альтернатива, если замер Electron покажет неприемлемые ресурсы; без замера это не объявляется доказанным.

Версии фиксировать lockfile при создании приложения после проверки совместимости. Существующие версии старого репозитория не копировать как «последние».

| Зависимость | Для чего нужна / почему |
|---|---|
| [React + TypeScript](https://react.dev/learn/typescript), Vite | Компоненты, строгие типы и быстрая обратная связь; выбранный CSS переносится напрямую. React — рекомендация, а не утверждение, что Svelte не подходит. |
| [Electron Forge](https://www.electronforge.io/) | Упаковка, native-модули и выпуск Mac-дистрибутива; исключает собственные скрипты сборки без необходимости. |
| [better-sqlite3](https://github.com/WiseLibs/better-sqlite3) + SQL-миграции | Локальное транзакционное хранение, одна точка записи, понятное резервирование. Native-модуль пересобирается под Electron ABI. |
| [Zod](https://zod.dev/) | Валидация команд/ответов IPC и изменений, полученных от AI. Типы сами по себе не защищают внешние данные. |
| [Ajv](https://ajv.js.org/) | Проверка строгого JSON Schema правил. Дубли ключей ловятся на этапе разбора до Ajv; ссылки и конфликты отдельным доменным линтером. |
| [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction) | Доступные диалоги/меню/select; стили собственные, без готового чужого визуального языка. |
| [dnd-kit](https://docs.dndkit.com/) | Доска с mouse/keyboard переносом. Статусное меню остаётся альтернативой. |
| [Temporal polyfill](https://github.com/js-temporal/temporal-polyfill) | Дата дня, точное время, часовой пояс и DST разделяются явно; оценка «рабочие дни» не подменяется часами. |
| [Vitest](https://vitest.dev/) + Playwright | Доменные/SQLite проверки и реальные пользовательские сценарии, снимки обеих тем; без тестов, повторяющих CSS-реализацию. |

Календарь первого выпуска — обзор фиксированных событий и сроков, поэтому не требует полного корпоративного календарного движка. Отдельную библиотеку выбирать после проверки пересечений и доступного списка событий.

## Хранение и процессы

Один владелец SQLite — выделенный repository worker приложения. Renderer общается только через узкий preload/IPC: команды с ID операции и ожидаемой версией снимка. Worker применяет проверенный пакет изменений одной транзакцией, пишет историю, возвращает новый снимок. Никаких независимых CLI/daemon-писателей. Экспорт включает версию формата, документы правил и вложения; восстановление проверяет всё до замены.

Пределы пакета экспорта: `manifest.json` — 1 MiB, `data.json` — 64 MiB, одно вложение — 100 MiB (как `AttachmentStore`), суммарный размер по manifest — 512 MiB. При проверке фактический размер каждого файла сверяется до чтения; вложения хэшируются и копируются блоками фиксированного размера.

Домен на TypeScript независим от React/Electron: состояния, повторения, доступность, риск, привязки, проверки изменения. Это подготовка к будущему телефону, **не готовая синхронизация**. Уникальные ID и версии полезны уже для локальных конфликтов. В renderer отключён Node, включены context isolation/sandbox; произвольные команды и файловые пути не проходят через IPC. Основание: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security).

## AI и источники

Предлагаемый путь — локальный Codex app-server по stdio через отдельный адаптер: диалог, поток ответа, auth/status, явные запросы и проверенные изменения. Документация описывает интеграцию в собственные клиенты и JSONL-транспорт; применение функций/динамических инструментов требует проверки совместимости выбранной версии. [Codex App Server](https://learn.chatgpt.com/docs/app-server).

Доступ по подписке, доступность модели, лимиты и условия для конкретного приложения **[проверить]** отдельным техническим экспериментом. Документация рекомендует Sign in with ChatGPT и указывает ограничения app-server auth для commercial/hosted сценариев. Локальный личный проект не считается доказательством бесконечного бесплатного доступа. Платный API не подставляется автоматически. Никакой реальный вход здесь не выполнялся.

AI не получает непосредственное право писать SQLite: предлагает типизированные команды, приложение проверяет ограничения/версию и применяет по режиму. Auto — только после явного запроса. Modeus — отдельный адаптер занятий с последним успешным снимком и давностью; API/вход **[проверить]**, задания не импортируются.

## Перенести / переписать / убрать

- **Перенести как материал:** доменные тестовые случаи сроков/конфликтов, идеи идемпотентности и транзакционной проверки, примеры интеграционных ошибок. Поведение сначала сверить с F-01–F-15.
- **Переписать:** модель задачи/повторов/колонок, сохранность и история, AI-контекст/команды, правила, источники, весь GUI. Алгоритм старой обязательной раскладки по часам не становится основой очереди дня.
- **Убрать из первого выпуска:** почту, ГОСТ-отчёты, самостоятельные процессы-писатели БД, фоновый AI-таймер, обязательный бюджет/опрос, старые ограничения на дни недели и будущую sync-инфраструктуру.

CI: typecheck → доменные проверки → реальные SQLite-транзакции/миграции → UI-сценарии/снимки → упаковка darwin/arm64 и Mac smoke. Подписание/нотаризация выполняются при выпуске с предоставленными владельцем реквизитами. Непроверенные характеристики ресурсов не превращать в числовой SLA.
