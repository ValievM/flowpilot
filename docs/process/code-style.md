# Стиль кода

Решение Claude (2026-10-05). Что можно проверить автоматикой, проверяет `npm run check` (TypeScript `strict`, ESLint, stylelint, dependency-cruiser). Здесь то, что автоматика не ловит. Нарушение без причины = замечание на ревью. Нужен компромисс: комментарий «почему» рядом и вопрос в issue.

## Общее
- Код и имена на английском, тексты для пользователя на русском. Тексты, которые повторяются или собираются из данных (склонения «1 / 2 / 5 рабочих дней», причины риска, сообщения об ошибках), живут в отдельном модуле `copy` рядом с экраном и покрыты тестом; одноразовые подписи можно писать литералом в разметке.
- Просто лучше умного. Меньше абстракций, чем кажется нужным; новая абстракция появляется, когда повторилось в трёх местах, и сразу с тестом.
- **Никаких «божественных» объектов, классов и файлов.** Один файл = одна ответственность. Модуль, который «знает всё» (`Manager`, `Service`, `Helper`, `Utils`, `Common`, `index.ts` со свалкой логики), запрещён: такие имена признак того, что ответственность не определена.
- **Жёсткие лимиты (проверяет линтер, `npm run check` падает; автоматика ставится задачей #32, до неё лимиты проверяет ревью):** файл до 300 строк; функция до 50 строк (в тестах `describe`/`it` вне лимита); не больше 4 параметров (больше: объект с именованными полями); цикломатическая сложность до 10; вложенность до 3; компонент React до 150 строк; не больше одного класса в файле (классы в доменном коде почти не нужны: функции и данные). Выход за лимит не обходят отключением правила: разделяют код. Исключение только с комментарием `// lint-exception: причина` и согласием Claude в issue.
- **Связность:** файл с более чем 10 публичными экспортами запрещён, но пока проверяется только на ревью вручную; автоматики нет. Цикл импортов (A импортирует B, B импортирует A) запрещён (dependency-cruiser `no-circular`). Данные и поведение, которые меняются вместе, лежат вместе; то, что меняется по разным причинам, разделено.
- Комментарий объясняет **почему**, а не что. Устаревший комментарий хуже отсутствующего. Без закомментированного кода, без «TODO» без номера issue.

## TypeScript
- Никаких `any`; `unknown` + сужение или Zod. `as` и `!` только с комментарием, почему безопасно. `// @ts-ignore` запрещён, `@ts-expect-error` только с пояснением.
- Состояния и варианты: дискриминируемые объединения (`{ kind: 'todo' } | { kind: 'waiting'; reason: string }`), а не флаги и необязательные поля. `switch` по `kind` с проверкой исчерпываемости (`assertNever`).
- Ожидаемые ошибки (валидация, «не найдено», конфликт версии) возвращай **значением** (`{ ok: true, value } | { ok: false, error }`), исключения только для багов и системных сбоев. `catch` не глотает ошибку молча.
- Неизменяемость: `readonly`, `ReadonlyArray`, функции возвращают новые значения. Мутация допустима только локально внутри функции.
- Экспортируй минимум. Имя типа описывает сущность (`Task`, `ColumnSemantics`), не `Data`/`Info`/`Manager`/`Utils`.
- Именование: файлы `kebab-case.ts`, типы и компоненты `PascalCase`, функции и переменные `camelCase`, константы `SCREAMING_SNAKE` только для настоящих констант. Булевы: `isX`, `hasX`, `canX`.
- Импорты: порядок и границы слоёв проверяет линтер и dependency-cruiser; вложенные «через слой» импорты не добавлять.

## Домен (`src/domain`)
- Чистые функции и неизменяемые данные. Никаких `Date`, `Date.now()`, `Math.random()`, `process`, файловой системы, `electron`, `react`, SQLite: «сегодня», «сейчас», идентификаторы и часовой пояс приходят аргументами или портами.
- Даты и время: Temporal (`PlainDate`, `PlainTime`, `ZonedDateTime`); день без времени и точное время не смешивать в одном поле.
- Функции видят весь вход и не лезут в глобальное состояние. Любое правило из спеки (`F-xx`) имеет тест, в имени теста указан `F-xx` или `AC-xx`.

## Хранилище (`src/storage`)
- Только main-процесс, единственный писатель. Запросы параметризованные (никакой конкатенации строк). Каждое изменение данных в транзакции, с записью в историю.
- Миграции нумерованные, неизменяемые после слияния в `dev`: исправление = новая миграция. Тест миграции на реальной временной БД из пустой и из предыдущей версии.
- Данные из БД и внешние данные проходят через Zod на границе.

## IPC и безопасность
- Контракты каналов в `src/shared` (Zod-схемы), один канал = одна узкая команда; команды, меняющие данные, несут ожидаемую версию (`expectedRevision`) и пакетом применяются одной транзакцией; ID операции добавляется там, где нужна идемпотентность повтора (создание карточек из AI, выпуск 2). Никаких «выполни произвольное», путей и команд от renderer.
- Renderer без Node, `contextIsolation`, `sandbox`. Вывод AI, содержимое вложений, файлы правил недоверенные: не исполняются, не вставляются как HTML (без `dangerouslySetInnerHTML`).
- Секреты только в Keychain; в логах, снимках, тестах и комментариях секретов и личных данных нет.

## React и интерфейс
- Функциональные компоненты и хуки; состояние держи рядом с использованием. Производное значение вычисляй, а не храни в `useState`. `useEffect` для синхронизации с внешним миром, не для вычислений. `useMemo`/`memo` только после измеримой проблемы.
- Компонент получает данные и колбэки через `props`; доступ к IPC через один слой (хук/сервис), не из каждого компонента.
- Стили только токены (`var(--…)` из `tokens.css`); никаких цветов, размеров шрифта и теней «на глаз» (stylelint). Анимации по `motion.md` с учётом «уменьшить движение».
- Доступность по умолчанию: семантические элементы, `aria-label` у кнопок-иконок, видимый фокус, управление с клавиатуры, контраст не хуже AA. Не передавать смысл только цветом.
- Любой новый экран сверяется с `docs/design/d-screens/` в двух темах и ширинах 900/1280/1440/1728.

## Тесты
- Имя теста описывает поведение предложением: «вчерашняя задача в работе видна сегодня с меткой переноса», не `test1`/`rollOver works`.
- Структура: подготовка, действие, проверка. Один тест = одно поведение. Без реального времени, сети, случайности: фиксированные часы, генератор id из теста, временная БД на каждый тест, фейки вместо моков.
- Не проверяй внутренности (приватные поля, вызовы функций): проверяй видимый результат. Домен не мокается.
- Новый тест с логикой доказан мутацией; тест, который не краснеет при поломке, бесполезен.
- Снимки (Playwright) только для принятых экранов; обновление эталона только осознанно и с описанием в сдаче.

## Коммиты
Маленькие, один смысл. Формат: `тип(область): суть` на английском, тип из `feat|fix|refactor|test|docs|chore|style`; в конце `Refs #N`. Секретов в diff нет (`git diff --staged` перед коммитом).
